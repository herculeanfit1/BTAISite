## Non-negotiables carried from this session

**Every plan is a dated hypothesis, not an instruction.** Three in a row contained
instructions that would have destroyed working code: PLAN-003 would have deleted the only
working backup script, PLAN-004 would have deleted the live backend and broken the contact
form, PLAN-005 would have deleted seven real API tests. Each was caught by the plan's own
verify-first step and none by reading the prose. Re-verify every claim against the code
before acting; when they disagree, the code wins and the plan gets an execution-notes
block.

**Availability.** Short downtime for a restart or provisioning is acceptable. Anything
longer needs approval first. Deploys are ~5 minutes and the site stays up through them;
the risk sits in PLAN-008 (routing) and PLAN-011 (infra), so verify on
`bridgingtrust.ai` — never only the `*.azurestaticapps.net` origin — and be ready to
revert.

**Never merge without being asked.** Branch → PR → CI green → stop. Merging six PRs today
was an explicit one-time instruction, not a standing change.

**Merging, when instructed.** Branch protection makes every merge push the rest to
`BEHIND`: `gh pr update-branch <n>` → wait for the _fresh_ run → `gh pr merge <n>
--squash`. Never `--admin`. Avoid stacked PRs where possible — they get no CI at all
(workflows filter `pull_request: branches: [main]`), and squash-merging the parent
conflicts the child.

**Verification hygiene.** Prove a sweep can see before trusting an empty result.
`git grep -E` does not support `\b`; `git check-ignore` needs `--no-index` to see tracked
files; a Vitest path filter matching zero files is silently ignored.
